# Validation codes

`raion validate` (and the server's workspace pages) report problems with a stable code. Errors (`RAI-E…`) block deployment. Warnings (`RAI-W…`) do not.

| Code     | Meaning                                                                                                                        | How to fix                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| RAI-E001 | YAML syntax error, or YAML that cannot be read (for example excessive alias expansion)                                         | Fix the YAML at the reported line. Indentation and unclosed brackets are the usual causes.               |
| RAI-E002 | `raion.yaml` missing, or it has no `kind: Workspace` document                                                                  | Run `raion init`, or point the command at the folder that contains `raion.yaml`                          |
| RAI-E003 | Document has a wrong `apiVersion` or unknown `kind`                                                                            | Use `apiVersion: raion/v1alpha1` and `kind: Workspace`, `Service` or `SLO`                               |
| RAI-E004 | A field is missing, has the wrong type or value, or is unknown (often a typo)                                                  | Read the message. It names the field and the allowed values.                                             |
| RAI-E005 | A `Workspace` document outside `raion.yaml`, or more than one                                                                  | Keep exactly one Workspace, in `raion.yaml`                                                              |
| RAI-E006 | A file is larger than 1 MiB, or there are more than 2000 files                                                                 | Split very large files. Remove unrelated YAML from `services/` and `slos/`.                              |
| RAI-E010 | Two services with the same name                                                                                                | Rename or remove one. The message says where the other is defined.                                       |
| RAI-E011 | A service belongs to a team that is not defined                                                                                | Add the team under `spec.teams`, or fix the spelling                                                     |
| RAI-E012 | A dependency names a service that does not exist                                                                               | Define the service, fix the spelling, or declare it as `external`                                        |
| RAI-E013 | An SLO refers to an unknown service                                                                                            | Fix `spec.service`                                                                                       |
| RAI-E014 | Two SLOs with the same name on one service                                                                                     | Rename one                                                                                               |
| RAI-E015 | A team routes alerts to an unknown receiver                                                                                    | Define it under `spec.notifications.receivers`, or use `inbox`                                           |
| RAI-E016 | A team or receiver name is defined twice                                                                                       | Remove the duplicate                                                                                     |
| RAI-E017 | A service's `environment` differs from the workspace environment                                                               | Use one workspace per environment                                                                        |
| RAI-E018 | An SLO is defined for a service whose metrics are disabled                                                                     | Set `signals.metrics: true`                                                                              |
| RAI-E019 | A runbook refers to an SLO the service does not have                                                                           | Fix the `slo` name                                                                                       |
| RAI-E020 | A service depends on itself                                                                                                    | Remove the entry                                                                                         |
| RAI-W101 | SLOs are defined but the `slos` feature is off at this level, so they will not be deployed                                     | Set `level: 3` or `features: { slos: true }`                                                             |
| RAI-W102 | A critical service has no team or owner                                                                                        | Set `team` or `owner`                                                                                    |
| RAI-W103 | The workspace has no services yet                                                                                              | Add one with `raion init --service <name>` or a file in `services/`                                      |
| RAI-E021 | An integration is not available (unknown name or version)                                                                      | Fix the name (a suggestion is shown); `raion connect` lists what is supported                            |
| RAI-E022 | A latency SLO threshold is not a bucket boundary of the service's request-duration histogram, so it cannot be measured exactly | Use one of the suggested values (e.g. 250 or 500 ms)                                                     |
| RAI-E023 | An integration parameter is unknown, has the wrong type or format, or a required one is missing                                | Use the parameters listed in the hint                                                                    |
| RAI-E024 | `containerLogs` is set on a service that runs on the host                                                                      | Remove it; container logs are collected only for Compose services                                        |
| RAI-E025 | A package in `integrations/` cannot be loaded (schema, placeholders, name)                                                     | Fix the package as the message says; see [Writing integrations](../integrations/writing-integrations.md) |
| RAI-E026 | A package in `integrations/` is not in `integrations.lock.yaml`, or changed since it was locked                                | Review the package, then run `raion integrations lock` and commit the lock file                          |
| RAI-W104 | An SLO needs HTTP request metrics, but no integration of the service provides them                                             | Set the service's `language` to a supported one, add an integration, or use a custom SLI                 |
| RAI-W105 | An integration is for a different language than the service                                                                    | Check `language` and `integrations`                                                                      |
| RAI-W106 | A runbook names an alert Raion does not generate for services                                                                  | Use an alert name from [Alerting](../09-alerts.md) or [Integrations](../integrations/README.md)          |
| RAI-W107 | A team route is set, but routing alerts to teams is a level-3 feature, so it is ignored                                        | Set `level: 3` or `features: { ownershipRouting: true }`, or use `notifications.defaultReceiver`         |
| RAI-W108 | `containerLogs` is set on a service that already sends its logs over OpenTelemetry, so each line would be stored twice         | Remove `containerLogs`, or set `signals: { logs: false }`                                                |
